# System #10 — Monitoring & Owner Control

Monitoring observes; it does not become authority. It records health, queues, failures and alerts and produces scope-isolated owner reports.

## Boundary
`OBSERVE -> RECORD -> ASSESS -> REPORT -> ALERT`

Monitoring never grants permissions, moves money, publishes content, deploys tools, joins communities, or changes security policy. Existing permission and security systems remain authoritative.

Security events may be surfaced to the authorized owner while internal defensive mechanisms remain quiet to unauthorized observers.

Plugin health is represented through the same monitoring boundary, so a failed specialist engine can be observed without becoming a core failure.
